# 내 브레인 개통하기

> 이 문서 하나만 따라 하면 됩니다. **20분** 걸립니다.
> 막히면 30분 넘게 붙잡지 마세요. 슬랙 `#10기-질문` 에 올리시면 됩니다.
> **개강 첫날 수업 후 30분 설치 클리닉**이 있으니 못 끝내도 진도에 지장 없습니다.

## 이게 뭔가요

메모와 문서를 넣어 두면, AI가 정리해서 **검색 가능한 위키**로 만들어 주는 개인 지식 저장소입니다. 우리는 이걸 "브레인"이라고 부릅니다.

앞으로 8주 동안 매주 배우는 기술이 이 브레인의 새 장기가 됩니다. 오늘은 빈 상자를 받아 전원을 켜는 것까지입니다.

**브레인 파일은 여러분 컴퓨터 안에 있습니다.** 강사도 열어 보지 않습니다.

다만 한 가지는 미리 알아 두세요. **키를 넣고 정리를 돌리면**(뒤에 나오는 LIVE 경로) 그때 그 메모의 내용이 AI 서비스로 전송됩니다. 요약과 분류를 AI 가 하기 때문입니다. 키 없이 쓰는 동안(RULE 경로)에는 아무것도 밖으로 나가지 않습니다. 무엇을 넣고 넣지 말아야 하는지는 [넣지 않을 것](#넣지-않을-것-반입-금칙)에 정리해 두었습니다.

## 빠른 시작

### 1단계. 내려받기 (5분)

먼저 **터미널**을 엽니다. 검은 화면에 글자를 입력하는 프로그램입니다. 엑셀에 수식을 적으면
계산해 주듯, 여기에 한 줄을 적으면 컴퓨터가 그 일을 합니다.

> 📸 화면 캡처 자리

**맥에서 여는 법**
1. `Command(⌘)` + `Space` 를 누릅니다
2. `터미널` 이라고 칩니다
3. Enter

**윈도우에서 여는 법**
1. 화면 왼쪽 아래 시작 버튼을 누릅니다
2. `PowerShell` 이라고 칩니다
3. `Windows PowerShell` 을 클릭합니다

> 윈도우에는 검은 창이 두 가지 있습니다. "명령 프롬프트"와 "PowerShell" 인데,
> **이 과정에서는 PowerShell 만 씁니다.** 헷갈리면 위 순서대로만 여세요.

검은 창이 뜨면 아래 두 줄을 복사해 붙여넣고 Enter 를 누릅니다.
붙여넣기는 맥이 `⌘ + V`, 윈도우는 **마우스 오른쪽 클릭**입니다.

```bash
git clone https://github.com/kimsanguine/llm-brain-edu.git
cd llm-brain-edu
```

**이 두 줄이 하는 일**

| 줄 | 하는 일 |
|---|---|
| `git clone …` | 인터넷에 올려둔 브레인 폴더를 내 컴퓨터로 통째로 복사합니다 |
| `cd llm-brain-edu` | 방금 받은 폴더 **안으로 들어갑니다**. 탐색기에서 폴더를 더블클릭하는 것과 같습니다 |

> `git` 은 파일을 주고받는 도구 이름입니다. 없다고 나오면
> [저장소 페이지](https://github.com/kimsanguine/llm-brain-edu)에서 **Code → Download ZIP** 으로
> 받아 압축을 풀고, 그 폴더로 들어가면 됩니다.

### 2단계. 준비물 설치 (5분)

브레인은 **파이썬**이라는 컴퓨터 언어로 만들어져 있습니다. 파이썬을 직접 설치하는 건
번거로워서, `uv` 라는 **심부름꾼 프로그램** 하나만 설치합니다. uv 가 파이썬과 필요한 부품을
알아서 받아다 줍니다.

> 프린터를 쓰려면 드라이버가 필요한 것과 비슷합니다. 그 설치를 uv 가 대신 해 줍니다.

**맥** — 터미널에 붙여넣고 Enter:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**윈도우** — PowerShell 에 붙여넣고 Enter:

```powershell
powershell -c "irm https://astral.sh/uv/install.ps1 | iex"
```

설치가 끝나면 **터미널 창을 닫고 새로 엽니다.** 새로 깐 프로그램은 창을 새로 열어야
인식됩니다. 그리고 1단계처럼 다시 폴더로 들어갑니다.

```bash
cd llm-brain-edu
uv sync
```

**`uv sync` 가 하는 일**: 브레인이 쓰는 부품 수십 개를 한 번에 받아 옵니다.
1~3분 걸리고, 글자가 주르륵 올라가는 것은 **정상**입니다. 멈춘 것처럼 보여도 기다리세요.

> **설치가 됐는지 어떻게 아나요?**
> uv 를 설치한 뒤 터미널을 새로 열고 `uv --version` 을 쳐 보세요.
> `uv 0.x.x` 처럼 번호가 나오면 성공입니다.
> `command not found` 가 나오면 아직 안 된 것이니, 터미널을 완전히 닫고 다시 열어 보세요.
>
> `uv sync` 는 마지막 줄에 `Installed ...` 같은 문구가 나오면 끝난 것입니다.
> **빨간 글씨가 보이면** 그 화면 전체를 복사해 슬랙 `#10기-질문` 에 올리세요.
> 혼자 30분 붙잡고 있지 마세요 — 설치 문제는 대부분 5분이면 풀립니다.

<details>
<summary>파이썬이 이미 있고 uv 를 쓰고 싶지 않다면</summary>

```bash
pip install -r requirements.txt
```

이 경우 아래 명령에서 `uv run python` 대신 `python` 을 쓰면 됩니다.
</details>

### 3단계. 설치 점검 → 초록불 (2분)

```bash
uv run python scripts/doctor.py --fix
uv run python scripts/doctor.py
```

두 번째 명령의 마지막 줄이 이렇게 나오면 성공입니다.

```
  ⚠️ openrouter-key: OPENROUTER_API_KEY 없음 — 없어도 설치는 완료입니다(RULE 경로로 동작)

요약: ✅ 40 · ⚠️ 1 · ❌ 0
✅ 설치 정상. (⚠️ 항목은 선택/환경별 — 필요 시 안내대로)
```

**⚠️ 1개는 정상입니다.** 아직 키를 안 넣었다는 뜻일 뿐이고, 키가 없어도 끝까지 진행됩니다.
❌ 가 0이면 성공입니다.

> **`RULE 경로`가 뭔가요?**
> 브레인이 메모를 정리하는 방식이 두 가지입니다.
>
> | 경로 | 언제 | 무엇을 하나 |
> |---|---|---|
> | **RULE** | 키가 없을 때 | 메모를 **그대로** 페이지로 옮깁니다. 정리는 안 하지만 위키는 만들어지고 검색도 됩니다 |
> | **LIVE** | 키가 있을 때 | AI 가 **요약하고 분류하고** 관련 페이지끼리 연결해 줍니다 |
>
> 지금은 RULE 로 갑니다. 키는 나중에 넣어도 되고, 안 넣어도 이 과정은 끝까지 됩니다.

### 4단계. 메모 3건 넣고 위키 만들기 (5분)

**여러분 업무 이야기로** 넣으세요. 아래는 직무별 예시입니다. 그대로 베끼지 말고
자기 일로 바꿔 적어야 8주 뒤에 쓸모가 생깁니다.

| 하는 일 | 이렇게 넣어 보세요 |
|---|---|
| 마케팅 | `"지난주 캠페인: 검색광고 CTR 2.1%, 소재 B가 A보다 전환 1.4배"` |
| 총무·행정 | `"과제 공고 요건: 신청 마감 3/14, 연구비 집행은 분기별 정산"` |
| 커머스 운영 | `"CS 반복 문의: 배송 지연 시 안내 문구는 3일 이상일 때만 발송"` |
| 기획·PM | `"회의 결정: 결제 실패 재시도는 2회까지, 그 뒤엔 사람이 확인"` |

```bash
uv run python scripts/ingest.py --note "여기에 내 이야기를 씁니다"
```

이 명령을 **세 번** 실행하면 메모 3건이 들어갑니다. 매번 따옴표 안의 내용만 바꾸세요.

> **`ingest` 가 무슨 뜻인가요?** "받아들이다" 라는 뜻입니다. 메모를 브레인 입구에
> 넣어 두는 단계이고, 아직 위키가 되지는 않았습니다. 위키로 만드는 건 다음 명령입니다.

이제 메모를 **위키**로 바꿉니다. 위키는 서로 연결되는 문서 묶음입니다.
같은 주제끼리 이어져서, 나중에 "그때 그거"를 찾을 수 있게 됩니다.

```bash
uv run python scripts/compile.py
```

**`compile` 이 하는 일**: 입구(`raw` 폴더)에 쌓인 메모를 읽어 위키 페이지(`wiki` 폴더)로
만듭니다. 원재료를 손질해 반찬으로 만드는 단계라고 생각하면 됩니다.

이렇게 나옵니다.

```
[compile] 메모 3건 → 위키 컴파일
  경로: RULE (OPENROUTER_API_KEY 없음 — 원문을 그대로 옮깁니다)
   ✓ wiki/concepts/2026-09-07-1358-note-2.md  [RULE]
   ✓ wiki/concepts/2026-09-07-1358-note-3.md  [RULE]
   ✓ wiki/concepts/2026-09-07-1358-note.md  [RULE]
  index.md 갱신 · 총 3개 페이지
[ingest] 3개 파일 처리 완료로 표시.
[compile] 완료 — 3개 페이지를 만들었습니다.
```

### 5단계. 눈으로 확인하고 캡처 (3분)

```bash
uv run python -m wiki_app
```

터미널에 **주소가 한 줄 찍힙니다.** 거기 적힌 주소를 브라우저에 넣으세요.

```
  브라우저에서 열어 보세요 →  http://localhost:8000
```

방금 넣은 메모 3개가 페이지로 보이면 완료입니다.

> **8000 이 아니라 8001 이라고 나올 수도 있습니다.** 정상입니다.
> 컴퓨터에서 다른 프로그램(주피터 노트북 등)이 이미 8000 번 자리를 쓰고 있으면
> 빈 자리를 찾아서 엽니다. 터미널에 찍힌 주소를 그대로 쓰면 됩니다.
> 아파트 주차장에서 내 자리가 차 있으면 옆 자리에 대는 것과 같습니다.

> 📸 **이 화면을 캡처해서 제출 폼에 올리세요.**

검색창에 아까 쓴 단어를 넣어 보세요. 찾아집니다. 끄려면 터미널에서 `Ctrl + C` 입니다.

## 안 될 때

여기서 막히는 건 **아주 흔한 일**이고 여러분 잘못이 아닙니다.

1. 오류 메시지 **전체**를 복사해 슬랙 `#10기-질문` 에 올립니다(스크린샷보다 텍스트가 낫습니다)
2. 어디까지 됐는지 한 줄 적습니다. "3단계 초록불까지 성공, 4단계에서 멈춤"
3. 설치 클리닉에서 함께 해결합니다

### 화면부터 보고 싶다면 (리커버리)

설치가 끝까지 안 되어도, 예제 위키를 넣어 화면이 어떻게 생겼는지 먼저 볼 수 있습니다.

```bash
uv run python scripts/compile.py --seed
uv run python -m wiki_app
```

여러분이 이미 만든 페이지가 있으면 덮어쓰지 않습니다. 나중에 `--seed` 없이 실행하면 내 메모로 만든 페이지가 추가됩니다. 예제 페이지는 자동으로 지워지지 않습니다.

## 키를 넣으면 뭐가 달라지나요 (선택)

지금은 `RULE` 경로로 돌고 있습니다. 메모 원문이 그대로 페이지가 됩니다. 위키는 잘 만들어지고 검색도 됩니다.

키를 넣으면 `LIVE` 경로가 되어, **AI가 요약하고 분류하고 관련 페이지끼리 연결**해 줍니다.

```bash
# 맥·리눅스
echo 'export OPENROUTER_API_KEY="발급받은키"' >> ~/.zshrc

# 윈도우
setx OPENROUTER_API_KEY "발급받은키"
```

**새 터미널을 열어야** 적용됩니다. 키 값을 화면에 출력하지 말고 설정 여부만 확인하세요.

```bash
# 맥·리눅스
printenv OPENROUTER_API_KEY >/dev/null && echo "설정됨" || echo "미설정"
```

```powershell
# 윈도우 PowerShell
if ($env:OPENROUTER_API_KEY) { "설정됨" } else { "미설정" }
```

같은 메모를 LIVE 경로로 다시 정리하려면 아래 명령을 실행합니다.

```bash
uv run python scripts/compile.py --recompile --dry-run
uv run python scripts/compile.py --recompile
```

`--recompile`은 처리 완료된 자료까지 다시 읽습니다. 키가 있으면 해당 자료가 AI 서비스로
전송되고 비용이 발생할 수 있습니다. 먼저 `--dry-run`으로 대상 목록을 확인하세요.
같은 출처의 페이지는 기존 경로에서 갱신됩니다. 이전 결과와 비교하려면 재실행 전에
민감정보가 없는 결과만 별도로 복사해 두세요.

이 버전으로 만든 메모는 `raw/`의 내용을 고친 뒤 `compile.py`를 실행하면 수정이 반영됩니다.
이전 배포판에서 이미 컴파일한 자료는 변경 감지 정보가 없으므로, 업데이트 후
`--recompile`을 한 번 실행해야 합니다. 그 뒤부터는 수정된 파일만 다시 처리됩니다.

> ⚠️ 키는 **비밀번호와 같습니다.** 슬랙·깃허브·과제 파일에 절대 붙여넣지 마세요.

## 넣지 않을 것 (반입 금칙)

파일은 내 컴퓨터 안에 있습니다. 다만 **키를 넣고 컴파일하면 그 메모의 내용이
AI 서비스로 전송됩니다.** 요약과 분류를 AI 가 하기 때문입니다. 그래서 규칙이 필요합니다.
**자산은 쌓기 전에 규칙을 정해야 합니다.** 한번 들어간 것은 되돌리기 어렵습니다.

| 어디까지 나가나 | 언제 |
|---|---|
| 내 컴퓨터 안에만 | 키가 없을 때(RULE 경로). 파일이 밖으로 안 나갑니다 |
| **AI 서비스로 전송** | 키를 넣고 `compile.py` 를 돌릴 때(LIVE 경로) |
| 다른 사람에게 | 브레인 폴더를 공유하거나 GitHub 에 올릴 때 |

**넣지 않습니다**

- 회사 기밀 문서 (계약서, 미공개 실적, 내부 전략 자료)
- 고객·동료의 개인정보 (주민번호·연락처·계좌·주소가 든 파일)
- 회사 규정상 외부 반출이 금지된 자료

**판단이 서지 않으면 넣지 않습니다.** 애매한 것을 넣고 후회하는 것보다, 안 넣고 아쉬운 편이 낫습니다.

**넣어도 좋은 것**: 내가 쓴 메모·회의 요약(민감정보 제거), 공개된 자료·기사, 학습 기록, 개인 아이디어

> **실수하면 알려 줍니다.** 주민등록번호나 카드번호로 보이는 값이 메모에 있으면
> 저장한 직후 터미널에 경고가 뜹니다.
>
> ```
>   ⚠️  방금 넣은 메모에 주민등록번호로 보이는 값이 있습니다.
> ```
>
> 막지는 않습니다 — 무엇을 넣을지는 여러분이 정합니다. 다만 모르고 지나치지는
> 않게 합니다. 경고가 떴는데 그대로 두고 싶지 않다면, `raw/notes/` 에서 그 파일을
> 열어 해당 줄을 고치고 `uv run python scripts/compile.py`를 실행하세요.
> 이전 배포판에서 만든 페이지라면 `--recompile`이 필요합니다.
>
> 신규 메모의 에피소드에는 본문 대신 저장 경로만 남깁니다. 다만 **이전 버전이 저장한
> 원문은 자동으로 지워지지 않습니다.** 아래 정리 절차를 확인하세요.
>

> 카드번호는 4자리씩 공백이나 하이픈으로 구분한 16자리 형식만 검사합니다.

### 이전 버전에 민감정보를 넣었다면

1. 웹 화면과 자동 수집 프로그램을 종료합니다. 정리하는 동안 키를 해제해 자료가
   다시 전송되지 않도록 합니다(맥: `unset OPENROUTER_API_KEY`, PowerShell:
   `Remove-Item Env:OPENROUTER_API_KEY -ErrorAction SilentlyContinue`).
2. 해당 `raw/` 파일을 로컬 편집기로 열어 민감값을 지웁니다. 파일명에 값이 있으면
   파일명도 바꾸고, 기존 파일명과 연결된 위키 페이지를 따로 확인합니다.
3. `episodes/`의 해당 월 `YYYY-MM.jsonl`을 로컬 편집기로 엽니다. 한 줄이 한 기록입니다.
   해당 메모가 남은 `user_goal`과 `inputs.source`의 문자열 값을 `[삭제됨]`으로 바꿉니다.
   줄 전체나 따옴표 구조를 손상시키지 마세요. 일반 실행은 원장을 수정하지 않으며,
   이 단계는 본인이 승인한 개인정보 정정 작업입니다.
4. `uv run python scripts/compile.py --recompile`으로 위키와 `index.md`, `wiki/graph.json`을
   갱신합니다. 키가 없는 RULE 경로인지 출력에서 확인하세요. 과거에 생긴 중복 페이지,
   직접 만든 요약, `express/`와 공유용 `okf/`, 백업에도 같은 값이 남았는지 확인합니다.
5. 이미 외부 AI에 전송했거나 파일을 공유했다면 로컬 수정으로 그 사본까지 회수되지는
   않습니다. 해당 서비스의 기록 관리와 공유본 정리를 별도로 진행하세요.

민감값이나 API 키가 보이는 터미널 화면, 파일, 검색 결과를 질문 채널에 올리지 마세요.

## 앞으로 8주

**앞의 다섯 주**는 브레인에 기능을 하나씩 붙입니다.

| 주차 | 브레인이 갖게 되는 것 |
|---|---|
| 10 | 눈 — 사진과 PDF를 읽습니다 |
| 11 | 의미 기억 — 흐릿하게 기억나는 것도 찾아집니다. 아침마다 스스로 자료를 먹습니다 |
| 12 | 입 — 출처를 달고 답합니다 |
| 13 | 손 — 다른 AI가 내 브레인에게 물어봅니다 |
| 14 | 신경계 — 흐름이 지도로 보입니다 |

**뒤의 세 주**는 그 브레인을 만든 방식 그대로, **여러분 업무 자동화 하나**를 짓습니다.

| 주차 | 하는 일 |
|---|---|
| 15 | 기획 — 내 업무 중 무엇을 자동화할지 정하고, 숫자로 목표를 세웁니다 |
| 16 | 빌드 — 실제로 만들어 돌아가게 합니다 |
| 17 | 증명 — 시간이 얼마나 줄었는지 숫자로 발표합니다 |

즉 앞의 다섯 주는 **연습**이고, 뒤의 세 주가 **여러분 것**입니다.

매주 만든 부품은 `extensions/` 폴더에 넣습니다. 자세한 규칙은 `extensions/README.md` 에 있습니다.

**본체(`scripts/`, `wiki_app/`)는 건드리지 않습니다.** 왜 그런지도 `extensions/README.md` 에 적어 두었습니다.

## 명령어 요약

| 하고 싶은 것 | 명령 |
|---|---|
| 설치 점검 | `uv run python scripts/doctor.py` |
| 메모 넣기 | `uv run python scripts/ingest.py --note "내용"` |
| 파일 넣기 | `uv run python scripts/ingest.py --file ~/문서/파일.pdf` |
| 위키 만들기 | `uv run python scripts/compile.py` |
| 화면 보기 | `uv run python -m wiki_app` → 터미널에 찍힌 주소 (보통 http://localhost:8000) |
| 예제로 화면 먼저 보기 | `uv run python scripts/compile.py --seed` |
