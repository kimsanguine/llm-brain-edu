# Ingest 규칙

## 역할
raw/ 파일을 읽고 wiki/ 페이지를 생성하거나 갱신한다.

## 절대 규칙 (위반 불가)

- raw/ 파일에 근거 없이 wiki/ 페이지를 신규 생성하지 않는다
- raw/ 파일에 근거 없이 기존 wiki/ 페이지의 사실 관계를 수정하지 않는다
- raw/ 파일 자체는 절대 수정하지 않는다
- query(질문) 응답 중에 wiki/ 파일을 수정하지 않는다
- Claude의 학습 데이터만으로 wiki를 채우지 않는다

## 처리 절차

### 1. 처리 대상 파일 식별
log.md의 마지막 ingest 타임스탬프 이후 raw/ 에 추가된 파일을 찾는다.

### 2. 각 raw 파일 처리
파일마다 아래 순서로 진행한다:

**a. 내용 파악**
- 파일의 핵심 주제, 등장하는 개념·도구·인물·프로젝트 식별
- `schema/domains.yaml`에서 도메인 분류 결정

**b. 기존 wiki 페이지 확인**
- `index.md`에서 관련 페이지 식별
- 기존 페이지가 있으면 → 갱신
- 없으면 → 신규 생성

**c. 페이지 생성/갱신 기준**
- 동일 개념이 3개 이상 raw 파일에 등장 → 독립 wiki 페이지 생성
- 단발성 언급 → 상위 개념 페이지에 섹션으로 추가
- TIL/meetings → 반복 패턴이 감지되면 `insights/` 페이지로 압축

**d. Cross-link 추가**
- 새 페이지에서 기존 wiki 페이지를 `[[페이지명]]`으로 연결
- 기존 페이지에서 새 페이지로의 역링크 추가
- Ghost 개념(언급됐지만 페이지 없음)은 link만 추가하고 index.md ghost 섹션에 등록

### 3. index.md 갱신
모든 파일 처리 후 index.md를 갱신한다.

### 4. log.md 기록
```
## YYYY-MM-DD HH:MM
- 처리: raw/파일경로 (N개)
- 신규: wiki/경로 (N개)
- 갱신: wiki/경로 (N개)
- Ghost 추가: 개념명 (N개)
```

## 페이지 품질 기준

- 핵심 요약: 2-3줄, 전문 용어 최소화
- 상세 내용: raw 파일에서 직접 인용하거나 요약. 추론은 명시
- 관련 개념: 최소 1개 이상의 `[[wikilink]]` 포함
- sources 프론트매터: 근거 raw 파일 경로 반드시 기재

## 노드 타입별 페이지 구조

### concepts/ (개념)
```
# 개념명
## 핵심 요약
## 작동 원리
## 활용 사례
## habix/강의와의 연결점  ← 이 항목이 cross-domain 연결의 핵심
## 관련 개념
```

### tools/ (도구)
```
# 도구명
## 핵심 요약
## 주요 기능
## 사용 패턴
## 주의사항 / 함정

```

### insights/ (인사이트)
```
# 인사이트 제목
## 핵심 원칙

```

### lecture/ (강의)
```

```

## Hard Dedup 규칙 (v0.3.0)

`scripts/ingest.py`가 `--url`·`--file`·`--note` 저장 **전에** `is_duplicate()`로 중복을 판정한다.

- 판정 기준: 저장 예정 파일명 slug(날짜 접두사 제거, `_`→`-`, 소문자)와 `index.md`의 `[[wikilink]]` 목록 완전일치. 반환은 `(is_dup, target_slug, score)` — v0.3.0은 완전일치만이므로 score는 1.0 또는 0.0.
- 중복이면 기본 동작은 **저장 보류**: raw 파일을 만들지 않고, episode도 기록하지 않으며, 기존 노드 `[[target_slug]]` 강화로 라우팅을 제안하는 메시지만 출력한다. 차단은 오류가 아니므로 exit 0.
- `--force` 플래그가 있을 때만 경고 후 기존처럼 저장을 강행한다.
- **자동 병합은 하지 않는다** — 라우팅은 제안 메시지까지. 기존 페이지 강화 여부는 사람이 결정한다.
- `--url` 경로도 slug가 URL에서 파생되므로 fetch 없이 저장 전에 차단된다.

## Capture Filter (v0.3.0)

`scripts/sync_raw.py`가 소스별 설정(`schema/sources.yaml`)으로 raw/ 복사 전에 잡음을 거른다.

- `require_keywords` (list): 나열된 키워드 중 **하나라도** 본문에 포함되면 통과 (대소문자 무시). 하나도 없으면 raw로 복사하지 않고 스킵 로그를 남긴다.
- `min_word_count` (int): 공백 분리 단어 수가 이 값 미만이면 복사하지 않는다.
- 두 필드 모두 선택 — 미설정 소스는 기존과 완전 동일하게 동작한다.
- `.md`·`.txt`만 본문 판정 대상이며, `pdf`·`docx`·`pptx`는 텍스트 판정 불가로 필터를 통과한다.
